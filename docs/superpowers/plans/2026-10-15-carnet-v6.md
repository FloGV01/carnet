# Carnet v6 — plan d'implémentation (version compacte)

> **Pour les agents :** sous-skill requis : superpowers:subagent-driven-development ou superpowers:executing-plans, tâche par tâche. Les étapes utilisent des cases à cocher (`- [ ]`). Plan compact, choisi par l'utilisateur le 15/10 : chaque tâche donne les fichiers, les interfaces, les tests à écrire en premier et les critères d'acceptation. Le code s'écrit à l'exécution, test d'abord.

**Objectif :** construire la v6 (« V2 ») décrite par la spec, livrée en une fois sous la version 6.0.0.

**Architecture :** l'humeur du jour (moyenne des humeurs du moment) devient la source unique de l'humeur pour toutes les analyses. Un module pur `analyse/comprendre.js` calcule les graphiques de l'écran Comprendre. La base passe en version 4 (store `notes`, trois listes) et la sauvegarde au format 4, en une seule migration. Le reste se compose d'écrans et de composants Preact qui lisent ces modules purs.

**Technique :**
- PWA sans build, Preact + htm vendorisés (`ui/lib.js`), IndexedDB ;
- tests : `node --test` à Paris et en UTC, Playwright (projets `iphone` et `chromium-sw`).

**Spec :** `docs/v6-specification.md` (fait foi).

## Contraintes globales

- Saisie du soir en moins de 30 s, un toucher enregistre, aucun bouton « Enregistrer », tout facultatif.
- Aucune mécanique d'engagement (série, score, badge, félicitation, compteur de jours), aucune alerte calculée, aucun conseil écrit par l'app, silence sur les jours non saisis.
- Zéro réseau, zéro CDN, CSP de `netlify.toml`, aucun style en ligne (couleurs par classes, tailles SVG par attributs).
- Pas d'étape de build : modules ES natifs, Preact + htm seulement via `public/js/ui/lib.js`.
- Sens des dépendances : seuls `ui/`, `app.js` et `main.js` importent `ui/` ou `vendor/`. `domain/`, `analyse/`, `db/` et `export/` sont purs, et la date du jour leur est passée en paramètre.
- Dates : tout passe par `domain/dates.js` (jour logique, bascule à 4 h, `jourEvenement`), jamais `toISOString().slice(0, 10)`.
- Listes `declencheur` et `dessous` jamais lissées. Les identifiants publiés ne changent plus.
- Mots interdits (`tests/aides/mots-interdits.js`) et test de vie privée sur tout nouveau texte, docs comprises : aucun prénom, aucune donnée réelle.
- `DB_VERSION` 4, `FORMAT_VERSION` 4, version de l'app 6.0.0.
- Avant chaque commit qui touche `public/` : `npm run precache`, puis `npm test`.
- Un commit par tâche :
  - message : `v6 (NN/26) : …` ;
  - dernière ligne : `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

**Commandes**
- unitaire :
  ```bash
  TZ=Europe/Paris node --test tests/unit/<f>.test.js
  ```
  puis la même commande avec `TZ=UTC` ;
- e2e :
  ```bash
  npx playwright test tests/e2e/<f>.spec.js --project=iphone
  ```
- calibration :
  ```bash
  npm run test:calibration
  ```

## Points de vigilance (à épingler par un test dans la tâche indiquée)

1. **Import d'une vraie sauvegarde ancienne**, avec des listes renommées ou archivées et un id inconnu. Rien n'est perdu, et les comptes restent justes au format 4 (tâches 02 et 06).
2. **Relevé d'humeur du moment noté à 01:00 le jour D+1, ou « vers 0 h ».** Il compte pour le jour D partout : humeur du jour, énergie basse, Mes jours, Comprendre (tâches 07, 12, 13 et 17).
3. **Jour qui n'a que des relevés « vers ».** Il a une humeur du jour, il reste hors de « Ta journée heure par heure », et la règle « Me ressourcer » ne joue pas (tâches 07, 12 et 22).
4. **Plusieurs années de données.** Aujourd'hui reste rapide malgré les mémos, et l'Analyse tient son budget de temps, humeur du jour comprise (tâches 01 et 09).
5. **Mode sombre, iPhone 390 × 797.** La page du soir tient sans défilement, sans le champ Humeur, avec le repli « pesé · rechargé » fermé (tâches 10, 11 et 26).
