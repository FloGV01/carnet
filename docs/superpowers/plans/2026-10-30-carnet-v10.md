# Carnet v10.0.0 : plan d'implémentation (compact)

> **Pour les agents :** à exécuter tâche par tâche (workflow ou superpowers:subagent-driven-development). Une tâche = un commit, relu puis corrigé avant la suivante.

**Objectif** : des exercices pour chaque moment (Moment difficile par état, six exercices nouveaux, propositions après une émotion, Bien-être par besoin, minuteurs et sons de fond), une carte des émotions qui grossit le mot du milieu pendant le glissement, et la police système partout.

**Architecture** :
- Le contenu reste pur dans `domain/` : exercices (`exercices.js`), souffle (`respiration.js`), et trois petits modules nouveaux (`propositions.js`, `favoris.js`, `entrees-bien-etre.js`).
- Un seul lecteur (`ui/composants/lecteur.js`) joue tous les exercices, en mode `bien-etre` (comme aujourd'hui) ou `crise` (règles des écrans de crise).
- Les sons de fond et les deux minuteurs sont des écrans pleins de l'onglet Bien-être ; le son vit sur son écran.

**Technique** : PWA sans build, Preact + htm (`ui/lib.js`), IndexedDB, Web Audio, `node --test` (Paris et UTC), Playwright (WebKit, iPhone 13, 390 × 844).

**Spec** : `docs/superpowers/specs/2026-10-30-carnet-v10-design.md`, qui fait foi, **§14 compris** (il prime sur les sections qu'il précise). États des lieux du code v9 (non suivis) : `.superpowers/v10/etat-carte.md`, `etat-moment-difficile.md`, `etat-bien-etre.md`, `etat-apres-emotion.md`, `etat-sons.md` ; ils listent les tests qui verrouillent l'existant.

## Contraintes globales

**Règles de CLAUDE.md**
- Un toucher enregistre, rien par défaut, tout facultatif. Aucune mécanique d'engagement (ni série, ni total de minutes, ni compteur de séances, ni coche de réussite, ni félicitation). Aucun avis clinique.
- Zéro réseau : aucun fichier son, aucune police, aucune image téléchargés. **Police système partout** : plus aucune `ui-serif` dans `public/`.
- CSP stricte : jamais d'attribut `style` écrit en texte ; classes CSS ou CSSOM. Pas de build. Sens des dépendances ; dates par `domain/dates.js`.
- Vocabulaire figé (roue, `declencheur`, `dessous`) : inchangé par la v10.

**Décisions de la spec à ne pas rediscuter** :
- Glisser la carte n'écrit jamais rien ; des cercles, pas de formes par émotion ; la double capsule reste au mot touché.
- Moment difficile : Panique · Colère · Trop-plein · Réveil la nuit, en haut ; un toucher **démarre aussitôt** ; pas de choix de durée ; son éteint au départ ; **pas de compte à rebours**, pas d'anneau, **pas de « Noter mon émotion »** ; « Réveil la nuit » sur fond noir, muet sauf voix.
- Bien-être : « Reprendre », favoris, puis **Me calmer vite · Dormir ou me rendormir · Me concentrer · Programme**, places fixes, pas de tri par l'heure.
- Après une émotion : « Pour ce moment : », pour les quatre zones, relevé neuf avec zone seulement.
- Sons de fond fabriqués par Web Audio (bruit brun, bruit rose, vagues, pluie douce), vivant sur leur écran.
- Textes d'exercice : une consigne par écran, phrases courtes, tutoiement, **aucune promesse** (liste `PROMESSES` de `tests/unit/exercices.test.js`), cycles entiers pour les étapes rythmées.

**Identifiants** (décidés ici, utilisés par toutes les tâches) :
- Exercices nouveaux, **ajoutés à la fin** de `EXERCICES` dans cet ordre : `soupir`, `expiration-longue`, `noting`, `ancrage-court`, `scan-court`, `savourer`, `panique`, `colere`, `trop-plein`, `reveil-nuit`.
- Éléments de Bien-être hors `EXERCICES` : `coherence` (existant), `minuteur`, `concentration`, `sons-de-fond`.
- Routes : `#/crise/:id` (onglet Aujourd'hui) ; `#/bien-etre/calmer`, `#/bien-etre/dormir`, `#/bien-etre/concentrer`, `#/exercice/:id`, `#/minuteur`, `#/concentration`, `#/sons` (onglet Bien-être). Les routes existantes ne changent pas.
- Méta : `favorisBienEtre` (liste d'identifiants) ; la méta `respiration` gagne `voix: boolean` (faux au départ).
- localStorage (préfixe `carnet:`, écrit seulement quand l'utilisateur change une valeur) : `carnet:bien-etre:dernier` (identifiant), `carnet:duree:<id>` (1, 3 ou 5), `carnet:minuteur` (`{ duree, intervalle }`), `carnet:concentration` (`{ duree, son }`), `carnet:sons` (`{ son, minuterie, volume }`).
- Séances : `exercice` = identifiant ci-dessus ; `origine` parmi les valeurs existantes (`moment-difficile` pour les exercices de crise, `bien-etre` pour le reste). Le minuteur silencieux est une séance (`exercice: 'minuteur'`) ; la concentration et les sons de fond n'en sont pas.

**Versions** : `DB_VERSION` 6 et `FORMAT_VERSION` 7 inchangés ; application **10.0.0** (tâche 9).

**Méthode**
- Avant chaque commit qui touche `public/` : `npm run precache`, puis `npm test` vert. Les tests cassés sont mis à jour dans le même commit, jamais affaiblis.
- Vérification visuelle en captures (WebKit 390 × 844, clair et sombre, gardées hors du dépôt) pour toute tâche qui touche l'écran.
- Commit « v10 (N/9) : … » avec `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Aucun push.

## Points de vigilance (relecture)

1. **Toucher juste après un glissement de la carte** (la lentille vient de bouger les bulles de 36 à 48 pt) : le mot choisi est celui sous le doigt au moment du toucher, ou rien ; jamais un voisin venu se placer là. Test : tâche 2.
2. **Exercice lancé depuis l'écran 3 avant la fin de la file d'écriture** (mot touché puis exercice aussitôt) : le relevé est complet en base (mot, énergie, activités touchées), et le lecteur démarre. Test : tâche 8.
3. **App cachée pendant un exercice ou un son** (verrouillage, autre app) : un exercice (crise ou Bien-être) et le minuteur silencieux se mettent en pause ; un son de fond continue tant que son écran est ouvert ; quitter l'écran des sons ne laisse aucun son orphelin. Tests : tâches 4 et 6.
4. **Favori ou « Reprendre » inconnu** (sauvegarde importée d'une autre version, clé abîmée, exercice retiré) : ignoré sans erreur ni ligne vide. Tests : tâches 3 et 7.
5. **Très grand texte** : les quatre boutons de Moment difficile, les quatre étiquettes du noting, les listes des entrées et la ligne « Pour ce moment : » tiennent sans débordement de côté. Tests : tâches 4, 5, 7 et 8.

### Tâche 2 : la carte suit le glissement

**Fichiers** : `public/js/ui/composants/carte-emotions.js`, `public/js/ui/carte-geometrie.js`, `public/css/ecrans.css` ; tests `tests/unit/carte-geometrie.test.js`, `tests/e2e/v9-emotion.spec.js` (et un fichier `tests/e2e/v10-carte.spec.js`).

**Produit** :
- `carte-geometrie.js` : `motDuMilieu(mots, point, precedent, seuil = 0.15) → id` (pur) : le mot dont la **place régulière** est la plus proche de `point` ; `precedent` est gardé tant qu'aucune autre place n'est plus proche d'au moins `seuil × PAS` ; égalité départagée par le plus haut (rang le plus grand) puis le plus à gauche (col la plus petite).
- `carte-emotions.js` : un écouteur `scroll` passif sur `.carte-defile`, regroupé par `requestAnimationFrame`. Quand `motDuMilieu` change, les places et échelles de `disposition(mots, idMilieu)` sont posées par CSSOM sur les bulles, **sans rendu Preact**. Le mot choisi garde `.choisi`, `aria-pressed` et sa double capsule à l'échelle que lui donne la lentille. À l'ouverture, la lentille se pose sur `motDuMilieu` du point de départ. Rien n'est branché en mouvement réduit (`reduit()`).
- Toucher : un toucher pendant un déplacement de la lentille ou dans les 350 ms qui suivent l'arrêt du défilement choisit l'élément **sous le doigt au moment du `pointerdown`** (et seulement si c'est le même au `click`), sinon il est ignoré.

**Tests** :
- unitaires : `motDuMilieu` (point sur une place, entre deux places, hystérésis gardée puis dépassée, égalité entre quatre mots) ; aucune bulle ne se chevauche pour chacun des 144 centres possibles (le test existant de `disposition()`, étendu) ; `etendue()` contient toutes ces dispositions ;
- e2e : faire défiler la carte de deux pas → le mot du milieu mesure 156 pt, ses voisins 120, aucun relevé en base, aucun `aria-pressed="true"`, pas de carte du bas ; mouvement réduit → toutes les bulles à 96 pt après défilement et `document.getAnimations()` vide ; point de vigilance 1 ; un toucher sur un mot après défilement le choisit et recentre la carte (v9 inchangé) ; les tests v9 cassés (l. 237-264, 518-602, 1057-1083) sont adaptés, pas affaiblis.
